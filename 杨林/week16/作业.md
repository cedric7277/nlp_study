## 0. 先看结论

如果只看架构路线，这一代模型已经明显分成四类：

1. **Qwen3.6 / Qwen3.8：Gated DeltaNet + 周期性 Full Attention**
   - 典型比例是 **3 层线性注意力 + 1 层全注意力**。
   - 线性层用 recurrent state 压缩历史信息，全注意力层周期性恢复精确 token-to-token 交互。
   - 27B Dense 和大规模 MoE 共用同一套宏观骨架。

2. **DeepSeek-V3：MLA + DeepSeekMoE**
   - 不采用 Qwen/Kimi 那种线性注意力混合。
   - 核心是 **Multi-head Latent Attention（MLA）低秩压缩 KV** + 细粒度 MoE。

3. **DeepSeek-V4 / GLM-5.2：对“历史 token 本身”做稀疏化**
   - DeepSeek-V4 用 **CSA + HCA + local sliding window**。
   - GLM-5.2 用 **MLA + DSA top-k token selection + IndexShare**。
   - 两者都更直接瞄准百万 token 场景中的 Attention FLOPs / KV Cache。

4. **Kimi-K3：KDA + Gated MLA + Attention Residuals**
   - 69 层 Kimi Delta Attention + 24 层 Gated MLA。
   - 既采用线性/递归状态路线，又保留 MLA，并加入 learned residual mixing、Latent MoE、SiTU-GLU。
   - 是这组模型里结构组合最激进的一类。

**最重要的一点：Qwen3.8-27B 与 Qwen3.6-27B 的语言主干结构几乎没有宏观变化。**  
两者当前公开配置中的层数、宽度、3:1 Gated DeltaNet / Gated Attention 排布、Attention heads、FFN 尺寸、原生 262K context 等关键结构参数一致。Qwen3.8-27B 的提升因此不能简单解释成“模型变宽/变深了”，而更应理解为**同一架构基础上的训练、后训练、Agent / Coding / Reasoning 能力升级**。

宏观排布：

```text
16 × [
  Gated DeltaNet → FFN
  Gated DeltaNet → FFN
  Gated DeltaNet → FFN
  Gated Attention → FFN
]
= 64 layers
```

也就是 **75% 线性注意力层 + 25% 全注意力层**。

## 2.2 Gated DeltaNet 在源码里到底干什么

Transformers 的 `Qwen3_5GatedDeltaNet` 并不是标准 Softmax Attention。

核心过程可以简化为：

```text
hidden
  ├─ Q/K/V projection
  ├─ depthwise causal Conv1d (kernel=4)
  ├─ beta gate
  ├─ decay gate g
  └─ gated delta rule recurrent state
          ↓
      current output
```

其状态更新直觉上类似：

```text
先衰减历史 state
→ 用当前 key 从 state 读取已有记忆
→ 计算 delta = 当前 value - 已有记忆
→ 按 beta 把这部分差值写回 state
→ 用 query 从更新后的 state 读取输出
```

因此生成阶段不需要像标准全注意力那样让每个线性层持续维护随序列长度线性增长的完整 KV 序列。

这就是 Qwen3.5/3.6/3.8 长上下文效率的重要来源。

## 2.3 Gated Attention

每第 4 层恢复一次普通 Attention 路径。

源码里的特点包括：

- Q / K RMSNorm；
- 24 Q heads / 4 KV heads，属于 GQA；
- 仅部分 head dimension 应用 RoPE；
- Q projection 同时产生 attention query 和 **output gate**；
- attention 输出乘 `sigmoid(gate)` 后再做 `o_proj`。

它的意义是：

> DeltaNet 擅长以固定状态压缩历史，但压缩必然损失部分 token 级细节；周期性全注意力负责重新建立精确的跨 token 交互。

# 6. DeepSeek-V3

DeepSeek-V3 是另一条路线：

```text
MLA + DeepSeekMoE
```

而不是：

```text
Linear Attention + periodic Full Attention
```

## 6.1 核心配置

- Main Model：**671B**
- Active：**37B**
- 另有约 14B MTP weights，因此 HF 完整权重体积口径可看到约 685B
- `hidden_size = 7168`
- `num_hidden_layers = 61`
- `intermediate_size = 18432`
- `moe_intermediate_size = 2048`
- 256 routed experts + 1 shared expert
- Top-8 experts / token
- `q_lora_rank = 1536`
- `kv_lora_rank = 512`
- `qk_nope_head_dim = 128`
- `qk_rope_head_dim = 64`
- official context：**128K**
- 当前公开 config 中 `max_position_embeddings = 163840`

> 这里要区分“官方对外宣称的可用 context”与配置对象的最大位置字段；两者不能机械视为同一个指标。

## 6.2 MLA 的关键思想

标准 MHA/GQA 在长上下文生成时要缓存 K、V。

MLA 则先把 KV 压到一个低维 latent：

```text
hidden
  ↓
KV low-rank compression
  ↓
latent KV
  ↓
再恢复/组合为 attention 所需 K/V
```

这使得 KV Cache 主要围绕低维 latent 保存，而不是完整多头 K/V。

因此 DeepSeek-V3 的长上下文效率主要来自：

**压缩 KV 表示**，而不是把多数 Attention 层改成 recurrent linear attention。

## 6.3 DeepSeekMoE

V3 采用：

- 大量细粒度 routed experts；
- shared expert 始终参与；
- 每 token 只激活 Top-8 routed experts；
- router 使用 sigmoid / bias correction 等方式做负载平衡；
- MTP 辅助训练。

所以 V3 的两个关键词是：

> **MLA 压 KV + fine-grained MoE 降 active compute**

## 7.3 CSA 与 HCA

### HCA：Heavily Compressed Attention

源码中的 HCA compressor 会把很长的一段 source tokens 聚合成更少的 compressed entries。

V4 配置里的压缩比序列中可看到 **128**：

```text
... 4, 128, 4, 128, ...
```

粗略理解：

```text
大量历史 token
    ↓
128:1 级别重压缩
    ↓
少量 compressed memory
    ↓
attention
```

它适合提供低成本的全局长程信息。

### CSA：Compressed Sparse Attention

CSA 的压缩粒度更细，配置中交替出现 **4**。

它先构造 compressed blocks，再借助 **Lightning Indexer** 从历史压缩块里选择 top-k，仅对选中的块做高成本计算。

所以 V4 不是“所有 token 两两 Attention”，而更像：

```text
最近局部 token：直接看
远处历史：先压缩
再索引最相关部分
最后做稀疏 attention
```

### Shared-KV MQA

V4 的 `num_key_value_heads = 1`。

Transformers 源码也直接把它描述成 **Shared-KV Multi-Query Attention**。

这进一步降低 KV cache。

---

## 7.4 mHC

V4 不再只有普通：

```text
x ← x + F(x)
```

而是使用多路 residual streams，并学习它们之间的组合。

配置：

```text
hc_mult = 4
hc_sinkhorn_iters = 20
```

可理解为维护 4 条 residual stream，再通过受约束的 mixing matrix 进行信息交换。

目标不是主要降低计算，而是：

- 深层网络信号传播；
- 训练稳定性；
- 提升超大模型可扩展性。

# 8. Kimi-K3

Kimi-K3 是这组里结构组合最复杂的一种。

## 8.1 模型规模

官方 Model Card：

- **2.8T total**
- **104B activated**
- **93 layers**
- 1 dense layer
- **69 KDA + 24 Gated MLA**

- 896 routed experts

- 2 shared experts

- Vision encoder：MoonViT-V2，约 401M
- quantization：MXFP4 weights / MXFP8 activations（QAT）

---

## 8.2 KDA：Kimi Delta Attention

KDA 与 Qwen Gated DeltaNet 属于同一大类：

> 用 recurrent state 代替完整 token × token attention matrix。

但 KDA 的 gate 更细。

源码中：

- Q/K/V 分开 projection；
- Q/K/V 各自有 short convolution；
- recurrent delta-rule state；
- gate 可以是 **full-rank / channel-wise**；
- 输出再经过 gated RMSNorm。

因此可以把两者粗略对比为：

```text
Qwen Gated DeltaNet
  → 更规整的多头 recurrent delta-rule

Kimi KDA
  → 更细粒度的 gating / channel-wise state control
```

这也是 Kimi 在超长上下文中选择 KDA 的主要原因。

---

## 8.3 Gated MLA

Kimi 的 24 个全注意力层不是普通 GQA，而是基于 DeepSeek 风格的 MLA：

- `q_lora_rank`
- `kv_lora_rank`
- NoPE / RoPE 分离
- latent KV
- attention output gate

所以 Kimi-K3 实际上把两条路线组合到一起：

```text
KDA recurrent memory
+
MLA compressed KV attention
```

---

## 8.4 Attention Residuals

Kimi 源码里还有一个非常值得注意的 `_apply_attn_res()`。

普通 residual：

```text
x_{l+1} = x_l + F_l(x_l)
```

Kimi 会保留一组 block residual candidates，然后：

1. RMS normalize；
2. learned projection 打分；
3. softmax；
4. 对多条 residual candidate 做加权和。

配置中：

```text
attn_res_block_size = 12
```

因此可以把它理解成：

> residual path 不再是固定相加，而是让模型动态决定“当前层应该从哪几条历史 residual stream 取信息”。

---

## 8.5 SiTU-GLU

源码实现：

```python
situ_a = beta * tanh(gate / beta) * sigmoid(gate)
```

并且 up branch 也可以做有界变换。

相比普通 SwiGLU，这相当于对激活幅度施加更明确的平滑约束。

## 9.2 DSA

`GlmMoeDsaIndexer` 的源码逻辑非常直接：

```text
query/key index projection
→ index score
→ ReLU
→ learned head weighting
→ causal mask
→ topk
```

最后：

```python
index_scores.topk(index_topk)
```

当前配置：

```text
index_topk = 2048
```

也就是说，在百万 token 上下文中，高成本 sparse attention 不需要对整个 1M 历史执行完整 attention，而是先从历史里选出大约 2048 个最相关位置。

与 Qwen/Kimi 的根本差别：

- Qwen / Kimi：大量层把**整个历史压成 recurrent state**；
- GLM：仍保留 token-level memory，但通过 indexer **只取相关 token 子集**。

---

## 9.3 IndexShare

GLM-5.2 的 `indexer_types` 不是每层都独立执行 top-k 检索。

当前模式开头为：

```text
full
full
full
shared
shared
shared
full
shared
shared
shared
full
...
```

也就是：

- 少数 `full` layer 真正计算 index；
- 后续 `shared` layer 直接复用上一个 full layer 的 top-k 结果。

Transformers 文档称之为 **IndexShare**。

官方说明它用于降低 1M context 下的 indexer FLOPs。

# 10. 四种长上下文路线放在一起看

## 10.1 Qwen3.8

```text
75% layer:
history → recurrent DeltaNet state

25% layer:
standard gated full attention
```

优势：

- decode state 比纯 KV cache 更可控；
- 结构规则；
- 线性层可流式更新。

代价：

- recurrent state 是压缩表示；
- 必须靠周期性 full attention 补 token-level 精确交互；
- 原生训练口径仍是 262K，1M 属于扩展能力。

---

## 10.2 DeepSeek-V4

```text
local recent tokens
+
compressed remote tokens
+
index-selected sparse blocks
```

优势：

- 直接围绕 1M context 设计；
- 极大降低长上下文 FLOPs 与 KV cache；
- HCA 提供全局低成本记忆，CSA 提供更精确的稀疏远程访问。

官方给出的设计目标对比中，V4-Pro 在 1M context 的 single-token inference 相对 V3.2：
- FLOPs 显著下降；
- KV cache 显著下降。

---

## 10.3 Kimi-K3

```text
69 KDA recurrent layers
+
24 MLA layers
+
Attention Residuals
```

优势：

- recurrent state + latent KV 两种压缩机制并用；
- 原生 1M；
- 多模态；
- residual mixing 本身也更灵活。

代价：

- 架构复杂；
- runtime 需要同时很好支持 KDA、MLA、MoE、AttnRes、量化和多模态。

---

## 10.4 GLM-5.2

```text
MLA compressed KV
+
DSA index → Top-2048 history tokens
+
IndexShare
```

优势：

- 保留 token-level 检索；
- 对超长上下文只在小子集上做高成本 attention；
- index 在多层之间复用。

代价：

- 需要额外 indexer；
- sparse top-k / cache layout 对推理引擎实现要求较高。

# 11. MoE 设计横向比较

| 模型 | Routed Experts | Routed / Token | Shared | Expert hidden / intermediate |
|---|---:|---:|---:|---:|
| Qwen3.6-35B-A3B | 256 | 8 | 1 | 512 |
| Qwen3.8-2.4T-A95B | 512 | 10 | 1 | 2048 |
| DeepSeek-V3 | 256 | 8 | 1 | 2048 |
| DeepSeek-V4-Flash | 256 | 6 | 1 | 2048 |
| DeepSeek-V4-Pro | 384 | 6 | 1 | 3072 |
| Kimi-K3 | 896 | 16 | 2 | 3072；另有 3584 latent MoE dim |
| GLM-5.2 | 256 | 8 | 1 | 2048 |

几个很明显的区别：

### Qwen3.8-A95B

更像“超大专家池 + 中等 Top-K”：

```text
512 experts
10 routed + 1 shared
```

### DeepSeek-V4

相比 V3，Top-K 从 8 降到 6，同时 Pro 扩大专家池到 384。

也就是更重视：

> **更大的参数容量，但严格压低每 token 激活 expert 数。**

### Kimi-K3

最激进：

```text
896 experts
16 routed + 2 shared
```

总模型与 Active 都非常大。

# 12. Attention 几何结构对比

> MLA 与普通 GQA/MQA 的 head 定义并不完全同构，因此不要只拿 `num_key_value_heads` 数字硬比。

| 模型 | 高成本 Attention 形式 | 关键维度 |
|---|---|---|
| Qwen3.8-27B | GQA + output gate | 24Q / 4KV，head 256，RoPE 64 |
| Qwen3.8-A95B | GQA + output gate | 64Q / 4KV，head 256，RoPE 64 |
| Qwen3.6-35B-A3B | GQA + output gate | 16Q / 2KV，head 256，RoPE 64 |
| DeepSeek-V3 | MLA | Q/KV low-rank；NoPE 128 + RoPE 64 |
| DeepSeek-V4-Flash | Shared-KV MQA + CSA/HCA | 64Q / 1KV，head 512 |
| DeepSeek-V4-Pro | Shared-KV MQA + CSA/HCA | 128Q / 1KV，head 512 |
| Kimi-K3 | Gated MLA | 96 heads；NoPE / RoPE latent attention |
| GLM-5.2 | MLA + DSA | NoPE 192 + RoPE 64；DSA index top-2048 |

# 13. 对 Qwen3.8 的定位

## 13.1 Qwen3.8-27B

它不是靠“更大”赢 Qwen3.6-27B：

```text
same 27B
same 64 layers
same hidden 5120
same 3:1 hybrid attention
same FFN size
same native context
```

它的价值在于：

- **部署尺寸不变**；
- 保留 native multimodal；
- 同样的成熟 Qwen3.5 backbone；
- 但训练 / 后训练能力明显向 coding、agent、long-horizon work 强化。

因此如果你的判断标准是：

> “同一显存 / 计算预算下，从 Qwen3.6-27B 升级有没有必要？”

从架构配置看，迁移成本相对低；它更像**同平台能力升级**。

---

## 13.2 Qwen3.8-2.4T-A95B

这是完全不同的部署级别。

它和：

- DeepSeek-V4-Pro：1.6T / 49B active；
- Kimi-K3：2.8T / 104B active；

属于同一个 frontier-scale 档位。

它的特点是：

1. **Active 95B 很高**；
2. 仍沿用 Qwen 的 3:1 DeltaNet / Attention 规则；
3. 512 experts；
4. 不是 Kimi 那样继续叠加大量新机制，而是对已经成熟的 Qwen backbone 做极限规模化。

因此它更像：

> **“架构复杂度适中，但把已有架构做得非常大”**

而 Kimi-K3 更像：

> **“同样超大规模，同时继续增加新结构自由度”**

DeepSeek-V4-Pro 则更像：

> **“超大 MoE + 极度面向 1M context 的稀疏/压缩 Attention 工程设计”**

---

# 14. 如果只从架构工程角度选模型

## 单机 / 较现实的本地部署

### 首先看 Qwen3.8-27B

原因：

- Dense 27B；
- 架构规则；
- 多模态；
- DeltaNet 有利于长序列状态管理；
- 和现有 Qwen3.5 / 3.6 runtime 生态高度接近。

如果已经能稳定跑 Qwen3.6-27B，3.8-27B 是最自然的升级路径。

---

## 极低 Active 参数的 MoE

### Qwen3.6-35B-A3B

35B 总参数、3B active，是这组里非常特殊的“低 active”方案。

它的目标明显偏：

> 用 MoE 获得比 3B Dense 更高的容量，但保持较低 token compute。

---

## 百万 token 长上下文优先

从**结构本身**而不是 benchmark 看：

### DeepSeek-V4 / GLM-5.2 更“原生地为 1M 做设计”

- V4：CSA/HCA/local window/Shared-KV MQA；
- GLM-5.2：DSA + Top-2048 + IndexShare；
- Kimi-K3：KDA + MLA，原生 1M。

Qwen3.8 也能扩到约 1M，但当前 Model Card 仍明确区分：

```text
262K native
≈1M extensible
```

这一点和直接把 1,048,576 写进 model config 的 V4 / Kimi / GLM 不完全相同。

---

## 超大模型容量优先

按总参数规模：

```text
Kimi-K3          2.8T
Qwen3.8-A95B     2.4T
DeepSeek-V4-Pro  1.6T
GLM-5.2          744B
DeepSeek-V3      671B

```

按 Active 规模：

```text

DeepSeek-V3       37B
DeepSeek-V4-Flash 13B

```

注意：

> **Active 参数不是实际 FLOPs 的完整等价物。**

Attention、linear attention、sparse indexer、vision encoder、MTP、expert implementation、precision 和 communication 都会改变真实吞吐。

# 16. 一句话总结每个模型

### Qwen3.8-27B
**Qwen3.6-27B 同骨架的新一代训练/后训练升级版；27B Dense 中偏部署友好，原生多模态。**

### Qwen3.8-2.4T-A95B
**把 Qwen 的 3:1 DeltaNet/Attention + MoE 架构推到 2.4T / 95B active 的 frontier scale。**

### Qwen3.6-27B
**Qwen3.5 hybrid architecture 的成熟 Dense 27B 基线。**

### Qwen3.6-35B-A3B
**同架构的极低 Active MoE：35B capacity、3B active。**

### DeepSeek-V3
**MLA + 细粒度 MoE 的经典路线，核心优势是 latent KV compression 与低 active compute。**

### DeepSeek-V4-Flash
**284B/13B active，把重点放在百万 token 的压缩/稀疏 Attention 效率。**

### DeepSeek-V4-Pro
**1.6T/49B active，在 V4 的 CSA/HCA + mHC 路线基础上进一步扩大容量。**

### Kimi-K3
**2.8T/104B active，KDA + Gated MLA + Attention Residuals + Latent MoE，结构创新密度最高。**

### GLM-5.2
**744B/~40B active，用 MLA + DSA Top-K + IndexShare 走“保留 token-level memory，但只访问相关历史”的路线。**

# 18. 核对注意事项

1. **总参数 / Active 参数并非普通 `config.json` 字段。**  
   这些聚合规模值采用官方 Model Card；配置文件主要用于核对层数、宽度、heads、专家数、Top-K、Context、LoRA rank、Attention layout 等结构字段。

2. **“Context Length”与 `max_position_embeddings` 不一定是同一个产品口径。**  
   DeepSeek-V3 就存在官方 128K 与当前配置 163,840 的差别；Qwen 则明确区分 262K native 与约 1M extensible。

3. **MLA 的 `num_key_value_heads` 不能直接与 GQA/MQA 做一维比较。**  
   MLA 先进行 latent compression，真正影响 KV cache 的关键量还包括 `kv_lora_rank`、NoPE/RoPE 分拆以及 cache implementation。

4. **MTP 训练配置不等于所有推理框架都会加载/使用 MTP。**  
   是否用于 speculative decoding 取决于具体 checkpoint 与 runtime。

5. **本文不混入 benchmark 结论。**  
   架构更复杂、总参数更大、Active 更高，都不自动等价于实际任务表现更强；任务能力还高度依赖数据、训练 recipe、post-training、tool harness 与 inference budget。

---

## 最终结论

如果把这一批模型按“最核心的工程思想”压缩成一句话：

> **Qwen3.8 用 recurrent DeltaNet 把大多数序列计算线性化；DeepSeek-V4 用压缩与稀疏选择减少真正参与 Attention 的历史；GLM-5.2 用 DSA 从完整历史里检索少数 token；Kimi-K3 则把 recurrent KDA、MLA、MoE 与 learned residual mixing 组合到了一起。**

而 Qwen3.8 自身最值得注意的两点是：

1. **27B：架构没有靠“换骨架”升级，说明 3.8 的主要进步来自训练体系。**
2. **2.4T-A95B：没有另造全新 attention 家族，而是把已经成熟的 Qwen3.5 hybrid backbone 直接扩到 frontier MoE 规模。**
